# Diario — 2026-07-06

Sesión larga: arrancó la tarde del 05 y cerró pasada la medianoche. Del sync de
memoria al **primer change de producto de Antimahue completo y en producción**:

  vacío, todo el proyecto vive bajo `inaction:antimahue.app`. Issue #2

  toolchain ya completos vía `setup-stack`; el DB schema de producto es lo

- **Deep-dive de autenticación.** Definido el modelo: Supabase Auth administra
  identidad (email+password), el PIN de 4 dígitos es **solo desbloqueo local**
  del dispositivo ya autenticado (D5) — no reemplaza el login. Se evaluó login
  social: Google y Facebook existen como providers de Supabase; **Instagram
  no** (su API de login quedó muerta hace tiempo). Decisión: **sin login
  social en el MVP** del staff — email+password una vez por dispositivo +
  reset por mail alcanza para dos usuarias. Google queda anotado a v2+ en
  `product-definition.md`, junto al Portal Público/Comunidad (que ya estaba
  documentado como v2+ de `color-palette-assistant`). Dominios reservados:
  `antimahue.com` / `.app` / `.page`.
- **Roadmap de MVP aprobado** — seis changes en orden: `data-model` →
  `auth-pin` → `catalogo` → `venta` → `dashboard` → `proveedores-dte` (al
  final: la carga inicial de stock es incremental por escáner, no depende del

  `catalogo`.
- **PR #16** — limpieza de docs: stack marcado como cerrado en
  `product-definition.md`, login social movido a v2+, eliminada una copia
  stale del design handoff.
- **Change `data-model`: ciclo SDD completo en la misma sesión.**
  - *Explore*: hallazgo clave que condicionó todo el diseño — un `GRANT` por
    columna no sirve porque admin y vendedor comparten el mismo rol Postgres
    `authenticated`; los costos de producto necesitan tabla propia
    (`producto_costos`), no una columna oculta.
  - *Proposal* aprobado con siete decisiones (D1–D7), incluida la convención
    de naming ES-dominio / EN-plataforma.
  - *Specs* (4 dominios: catalogo, venta, configuracion, seguridad — 17 REQs)
    y *design* (RPCs `SECURITY DEFINER` como único camino de escritura, dinero
    en `integer` CLP) en paralelo.
  - *Tasks*: 24 tareas atómicas.
  - *Apply* → **PR #18**: 3 migraciones (`domain_tables`, `domain_rls`,
    `domain_rpc`). Conflicto detectado entre specs (`numeric`) y design
    (`integer`) para columnas de dinero — saneado a `integer` (commit
    `b9c6cd8`).
  - *Review de seguridad adversarial*: veredicto MERGE-SAFE, 0 CRITICAL.
    Hallazgo **W1 real**: los `ALTER DEFAULT PRIVILEGES` de Supabase otorgan
    escrituras residuales a `anon`/`authenticated` en toda tabla nueva — las
    migraciones no las revocaban explícitamente. Fix aplicado (commit
    `b91648d`, `REVOKE` explícito). Gate local con `podman` corrido dos veces,
    PASS ambas.
  - *Deploy* a producción, *verify* contra prod: **PASS** (0 CRITICAL, 3
    WARN) — matriz de privilegios verificada tabla por tabla, REST como
    `anon` devuelve 401 en los cinco endpoints probados.
  - **PR #19**: verify-report + estado honesto de la fase 5 (los escenarios
    ligados a JWT real quedan parciales/diferidos, no se inventó un PASS que
    no existía).
  - *Archive* → **PR #20**: specs consolidadas a `openspec/specs/`, change
    movido a `openspec/changes/archive/2026-07-06-data-model/`.
- **El deploy path — la historia del día.** El merge de #18 no disparó ningún
  deploy. Causa: la integración GitHub↔Supabase tenía el toggle "Deploy to
  production" **apagado desde el origen del proyecto** (por eso en junio,
  para `setup-stack`, también hubo que deployar a mano). Se destrabó vía MCP
  `execute_sql` + registro manual de versiones con el prefijo exacto del
  filename (el fallback sancionado — `apply_migration` del MCP sigue
  prohibido porque registra el timestamp de ejecución, no el del archivo).
  El usuario activó el toggle (branch `main`, working dir `.`); quedó
  verificado end-to-end con el merge de #19, que produjo el primer check-run
  `deploy: success` de la historia del repo — registry 4/4, cero
  re-ejecuciones. Documentado en `CLAUDE.md`.
- **Cifras de la sesión**: 5 PRs mergeados (#16–#20), cero pushes directos a
