REQ-SETUP-6/7/8 · D4/D5 · T2/T5/T7
  • 3.1

    Escribir la tabla profiles en la migración conforme al esquema exacto de REQ-SETUP-8: id uuid PK → auth.users(id) ON DELETE CASCADE, rol text NOT NULL DEFAULT 'admin' CHECK (rol IN ('admin')), created_at timestamptz DEFAULT now().

    SEGURIDAD — crítico
  • 3.2

    Añadir ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY; — deny-by-default (sin política = sin acceso, REQ-SETUP-7, T2).

    SEGURIDAD — crítico
  • 3.3

    Escribir el SQL del trigger de registro (no incluido en la especificación, debe estar aquí): función public.handle_new_user() con SECURITY DEFINER que inserta en profiles al crear un usuario en auth.users.

    CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger AS $$
BEGIN
  INSERT INTO public.profiles(id) VALUES (NEW.id);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE PROCEDURE public.handle_new_user();
    SEGURIDAD — crítico
  • 3.4

    Crear la tabla auth_attempts para el throttle replicado en servidor (defensa en profundidad, D5, T5):

    CREATE TABLE public.auth_attempts (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id      uuid REFERENCES auth.users(id),
  attempted_at timestamptz DEFAULT now(),
  success      boolean NOT NULL
);
ALTER TABLE public.auth_attempts ENABLE ROW LEVEL SECURITY;
    SEGURIDAD — crítico

  action    text NOT NULL,
  entity    text,
